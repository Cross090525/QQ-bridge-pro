# 用量与额度

控制台“用量与额度”统一设置图片、视频、语音识别、普通模型唤醒、争论分析批次、文字/图片/表情发送、语音发送、表情收藏、黑话提交、反馈与已注册扩展能力的次数预算。默认关闭，具体额度由管理员在控制台设置。

每条规则选择资源、次数、窗口分钟，以及全局共用、各会话分别或指定会话三种范围。多个规则同时约束同一操作，全部有余额才可执行。窗口从首次使用开始；达到上限只暂缓该能力，**窗口结束后自动恢复**，无需人工批准。后台到期计时器会重新安排被额度阻塞的观察，不依赖管理员打开页面或群友发送新消息。普通文字入库不会因图片或视频额度暂满而停止。

达限时，管理员私聊收到当前用量、范围、自动恢复时间和一次提前重置申请。可在控制台批准/拒绝，或由 ownerQQ 本人在机器人私聊发送 `/quota-approve 申请编号`、`/quota-deny 申请编号`。批准只将对应额度归零，并从批准时间开始一个完整新窗口；拒绝只拒绝提前恢复，不影响正常到期恢复。旧窗口过期后，原申请失效；重复批准不能重复赠送额度。其他群成员、群内管理员口令、会话智能体与争论任务凭据均不能配置或重置额度。

用量文件 `state/usage-quotas.json` 保存窗口起点、次数及申请元信息，**不保存永久达限锁定标记**。重启会恢复当前窗口已用次数，避免重启意外赠送额度；是否暂满由当前时间、窗口期限和已用次数重新计算，过期立即恢复。配置文件只保存规则；普通 `/reset` 不清除窗口用量。损坏的用量文件不会被自动覆盖为空，需恢复备份。管理员主动修改额度规则、关闭机制属于管理操作。

## 计数范围

读取/调用在执行前预占次数，失败不退还，防止持续失败重试造成额外开销。并发任务同步检查并占用，不能超卖最后一次额度；已经占用的最后一次允许完成。提前重置保留已经完成的读取结果，等待中的任务从未完成处继续。缓存命中不占媒体读取额度；扩展接口的缓存请求仍计入该扩展的调用次数。

| 控制台资源 | 标识 | 计数单位 |
| --- | --- | --- |
| 图片/表情读取 | `media.image` | 读取一次图片/表情来源；自动和按需工具共用 |
| 视频读取 | `media.video` | 一次视频准备；同一自动任务中的抽帧和转写共用一次，不按帧计数 |
| 语音识别 | `media.audio` | 一次获准的语音/音频识别 |
| 普通模型唤醒 | `model.wake` | 一次二代普通观察/聊天唤醒尝试，不代表 token 数 |
| 争论分析批次 | `debate.analysis` | 一次非空分析批次，不代表实际模型回合数 |
| 文字/图片/表情发送 | `send.message` | 每个实际提交网关的消息分条或媒体消息 |
| 语音发送 | `send.voice` | 每条语音提交尝试，与普通发送分开 |
| 表情收藏/黑话/反馈 | `sticker.collect`、`slang.submit`、`feedback.submit` | 每次提交尝试 |
| 扩展服务/记忆提供者 | `extension.能力标识` | 每次已通过原有权限检查的能力调用，能力标识来自扩展管理 |

不会因额度充足而获得新权限，ask/deny、群白名单、模式、暂停、静默与数据范围仍需满足。单次文件体积、视频时长、消息长度和并发容量等处理边界照常生效，不属于时间窗口预算。桥接之外直接执行的模型回合或独立工具不在此计数范围内；此模块不是整个 DSH 的 token/费用账单。

勾选“继承现有次数限制”后，原有分钟/小时次数限制也使用本机制的自动恢复和提前重置；原有数值仍通过对应控制台配置调整。取消勾选后，次数预算只按自定义规则执行。机制关闭时保留原有次数检查行为。

## 配置与接口

```json
{
  "quotas": {
    "enabled": true,
    "includeExisting": true,
    "rules": [
      {"id":"images","resource":"media.image","scope":"global","limit":20,"windowMinutes":60},
      {"id":"videos","resource":"media.video","scope":"conversation","limit":3,"windowMinutes":60}
    ]
  }
}
```

以上仅是配置示例，不会自动应用。scope=exact 时另填 `key:"group:456"` 或对应私聊。每条1–1000000次、1–43200分钟，最多100条规则。窗口状态最多4096条。

管理员接口继承控制台令牌、Origin 和 JSON 请求体检查：

| 接口 | 用途 |
| --- | --- |
| `GET /api/quotas/status` | 配置、当前次数、恢复时间、剩余时间及申请状态 |
| `POST /api/quotas/config` | 保存 `{enabled,includeExisting,rules}` |
| `POST /api/quotas/review` | `{requestId,decision:"approve"/"deny"}` 提前重置审核 |
| `POST /api/quotas/request` | `{bucketId}` 由管理员重新发起已拒绝的提前重置申请 |

验证：`npm run test:quotas`、`npm run test:quotas:ui`。均使用隔离桥接，测试不会调用真实模型或发送真实 QQ 消息。

## 等待额度与任务续行

遇到时间窗口额度不足时，原调用挂起等待额度恢复，不要求模型从头重试。自动恢复与管理员提前重置都会唤醒原任务；同一任务从首次额度不足开始共享5分钟等待期限，分页、再次触顶和提前重置均不延长期限。权限撤销、暂停、调用方断开或桥接关闭会取消等待。

5分钟后停止补读，返回已取得的部分结果及明确的未知范围，要求模型按已有信息回应。发送或普通唤醒本身也因额度不足而超时时，仅放行该任务一次最终文字发送/唤醒以完成超时回应；不放宽白名单、原有审批、静默及凭据检查。争论分析最多放行一次最终分析，逐条审核模式仍保留审核。执行失败或结果不明确的外部写入、QQ发送不会自动重发。

图片读取保留有界的短期结果缓存；多图工具按 nextOffset 分页续读，超时保留此前成功读取的图片。同一来源已提供的证据及永久失败状态会保留，避免旧媒体缓存淘汰后反复下载、唤醒和消耗额度。长等待工具在媒体未完成时先交付媒体证据，避免在“潜水”等待中挡住剩余图片。重启会取消内存中的等待调用，窗口用量依旧保留。

额度恰好用完但任务已完成时，不发送提前重置通知。只有后续任务实际被该额度阻塞时，才通知管理员；同一窗口同一申请只通知一次。管理员仍可在控制台按需提前重置已用完的额度。
