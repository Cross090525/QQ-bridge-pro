# 实时工作记忆与自动观察

时效事实、持久化未完事项和相关接续见[时效记忆与未完事项](TEMPORAL_TASK_MEMORY.md)。长文积压、来源回执、删除失效和原消息时间也按该文档的新规则处理。

当前消息与历史参考使用消息级时效标记，自动快照默认仅带入两小时内原文。已处理或过时消息标为历史参考，普通群聊回复和引用在发送前校验当前依据。具体窗口与用户重新引用旧消息的规则见上述指南。

二代仿真模式默认持续观察获准会话，再决定是否发言。普通群消息会合批触发观察，@、名字和关键词仍用于提升唤醒优先级。白名单、暂停、会话串行队列和[统一额度](USAGE_QUOTAS.md)继续生效；限频时消息仍保存，不保证每个短句单独触发一次模型调用。

在控制台「二代仿真 → 实时工作记忆」查看状态或关闭。配置项为 `socialV2.workingMemory.enabled`，缺省为 `true`。关闭 `getRecent` 或 `contextQuery` 也会停止该功能。保存后对后续批次生效；QQ 预设与 MCP 工具更新需要重启 DSH。此功能不写入长期记忆提供者、不修改角色卡或黑话库。

## 观察节奏与额度

`model.wake` 统计模型观察、判断与整理的唤醒次数。模型最后选择观察或沉默时，这次调用仍计入额度。QQ 实际发送另用 `send.message` 计数，两项预算各自处理。

连续普通群消息会按 `socialV2.workingMemory.observationIntervalMs` 合并。默认值为 60000，表示距离最近一次模型唤醒至少 60 秒后再执行纯观察批次，安静较久后的第一批仍走原有短窗口。范围为 0 至 600000 毫秒，0 可关闭额外间隔。原文继续即时入库。合并期间若当前回合已处理全部来源，到期批次会跳过，减少重复消耗。

@、私聊、关键词等明确触发遵循各自的原有合并窗口，@ 和管理员手动唤醒可以提前接管已排队的纯观察批次。已经在运行的模型回合继续遵循会话串行规则，唤醒机会仍由当前消息判断是否发言。

控制台「实时工作记忆」可调整观察间隔。「唤醒状态」显示待执行批次时间，额度等待时显示本次等待截止与额度窗口恢复时间，日志原因记为 `quotaWait`。现有额度等待有五分钟上限，`wakeQuotaWaiting` 在退出等待时清理。短时间内看到该状态应结合后续实际唤醒及额度状态判断。

配置调整对后续批次生效。测试 `npm run test:wake-silence` 覆盖观察合并、明确触发提前接管、已处理批次跳过、沉默观察计数和等待自动结束。

## 长对话中的角色保持

管理员选定的角色卡会随二代会话的每次模型输入重新提供，放在消息与工作记忆之后。`qq_get_unread_messages`、`qq_get_recent_messages`、`qq_wait_for_messages` 和工作记忆读取的会话响应也带有当前 `role:{name,version,hint}`，长时间在同一回合里等消息时不必依赖早期工具结果保存人设。角色文本按二代模式筛选，继续遵循控制台的角色注入上限（默认6000字符）；不会因聊天积压或上下文策略改为只提供名字和哈希。

角色编辑后在下一次输入或读取/等待响应中生效，清除角色时返回 `name:null` 与空 `hint`，提醒模型停止沿用已取消的人设。此行为独立于实时工作记忆开关、`context.strategy` 和 `getPrompt` 发现工具的开关；管理员任务模式不注入群聊人设，拒绝或过期请求也不附带角色卡。群聊原文、旧摘要、媒体分析和通用梗参考不能覆盖当前角色。

持续提供角色卡会增加每次输入和上述工具响应的字符/token开销，换取角色不依赖早期历史。它保证当前角色文本仍在输入中，真实模型的语气和性格稳定性仍需通过长对话验证。不会自动重写角色卡、提高模型温度或停用上下文压缩。

## 群聊中的对象与参与判断

持续观察不等于每条都回复。二代群聊默认先观察，明确叫机器人、确实延续与机器人的交流，或开放话题里有具体新信息时才考虑发言。问号、第二人称、提到机器人名字、热闹程度和机器人刚说过话都不能单独证明当前消息在对它说。明确指向他人的问答通常不代答；未知归属先保留不确定性。自然参与开放话题仍被允许，不限制为只有@才能回复。

新的原文记录保留 `addressing:{mentionedUserIds,mentionsSelf,mentionsAll,replyTarget,replyToUserId}` 及 `replyToMessageId`。@对象只取真实OneBot段；引用来源经过当前会话检查，`replyTarget` 为 none/self/other/unknown，查询失败或无法确认时为unknown。不会从文本里的“@某人”、图片或引用原文推定真实@。这些字段保存在近期消息与工作记忆中，随唤醒、未读、近期消息及等待结果提供；旧记录缺少的信息不自动猜补。

当前模型输入和读取/等待响应还会提供 `participation` 对象与参与规则，使已有长会话也能在下一次输入中获得边界提醒。私聊仍按对方当前发言自然回应，管理员任务模式保持独立。机器人无需向群里报告观察、解析进度或“与我无关”。该机制提供可核验的对象信息与判断规则，不替模型证明每次自然语言指代都正确；真实群聊仍需评估误接话与漏回复。

接话尺度、单群覆盖、参与状态和发送前复核见[接话与参与管理](PARTICIPATION.md)。`npm run test:participation` 使用隔离网关验证@其他人、@机器人、@全体、引用别人/机器人、未知引用、跨群隔离、策略管理，以及读消息、持续等待和发送路径。

## 三层上下文

1. 原文：每会话最多 500 条近期消息，保留发送者、时间、QQ 消息 ID、引用对象、媒体引用及实际发送的回复。单条最多 12000 字符，超过时明确标注；旧近期缓存只在首次启用时导入，并注明可能是节选。
2. 工作状态：最多 5 个话题，以及各最多 10 条事实、问题和不确定项。每项带来源编号、更新时间、状态（active/dormant/resolved）和确定性（reported/confirmed/inferred）。活跃话题一小时未更新，在快照中显示为 dormant；不会把未回答问题自动认定为已解决。
3. 模型快照：每次唤醒自动提供，独立于旧 `context.strategy`。默认优先带入最早尚未判断的 12 条消息和最近 8 条，去重并按原顺序排列；总预算约 10000 字符。长消息先给头尾节选，完整缓存可按编号回看。模型提交参与决策后记录已展示的判断进度，有积压时安排后续观察；预算截断不授予未展示消息的已读水位。

消息展示、模型判断、媒体理解、实际发言是不同状态。`mark_read` 和潜水不删除工作记忆；`reply` 决策不是成功发送记录。状态按会话散列文件名保存在 `state/working-memory/`，原子写入并在重启后恢复。损坏文件不会被空状态覆盖，需恢复备份。

## 自动感知

图片通过现有获准看图能力获取；视频与语音按已配置的固定只读服务准备证据。兼容 `bilibili.storyboard`、`media.storyboard`，也支持 main 现有的 frames/transcript 服务组合，不安装或改写服务配置。普通网页链接没有视频服务时不会被当作视频理解。

后台全局最多 2 个准备任务同时运行，最多 32 个排队，每批最多调度 5 个来源。文字观察最多等 2.5 秒，未完成的媒体标记 pending；完成后重新安排观察。每轮最多直接携带 5 张图片，超过预算的证据留待后续批次。抽样视频及超长识别结果的节选必须保留范围限制。

只有明确 allow 的只读服务可以自动执行，ask/deny 不自动申请审批、不绕过人工授权。权限、会话身份、暂停、模式或工具配置变化会使在途结果失效。媒体状态 prepared 只表示证据准备好；模型实际看到证据并提交摘要后才是 understood。失败或过期表示未知，不代表与机器人无关。

## 模型更新接口

工具 `qq_working_memory` 的 read 返回快照；可用 `input.query` 搜索原文，或 `input.messageId` 按工作记忆的 `messages.id` 精确回看。update 通过 `input` 提交：

```json
{
  "revision": 0,
  "topics": [{"text":"大家在讨论刚才视频里的剧情", "status":"active", "certainty":"reported", "sources":["qq:100"]}],
  "decision": {"action":"need_context", "note":"视频仍在解析，先补充信息", "sources":["qq:100"]}
}
```

更新字段仅支持 `revision`、`topics`、`facts`、`questions`、`uncertainties`、`media`、`decision`。列表字段为完整替换，无变化时省略；不要省略仍有效的条目。`decision.action` 可为 observe/need_context/reply，只保存简短依据，不保存完整思考。媒体更新使用 `media:[{sourceId,summary}]`，只能总结已经提供证据的来源。

所有来源必须属于当前会话且确实展示过，管理端预览不算模型已读。revision 冲突返回 409，模型须重新读取并合并；新消息入库与媒体准备不覆盖语义状态。没有新模型判断时，控制台保留“尚未判断”或上次决策，不能保证模型每轮都遵循协议。

外部程序可用 `QQBridgeClient.workingContext({query,messageId})` 和 `updateWorkingContext(input)`；对应 GET/POST `/api/v1/working/context`，只用当前会话令牌。该接口不开放跨群、管理员任务模式、文件路径或长期记忆写入能力。

## 验证

`npm run test:working-memory` 验证持久化、消息积压、已读水位、版本与来源约束、权限撤销及真实 HTTP 媒体服务；`npm run test:working-memory:ui` 使用隔离桥接和真实浏览器验证控制台。测试不向真实 QQ 发消息，不调用真实模型。实际是否自然接话还需部署后用群聊样例评估。

## 新来信、等待与已读

消息类唤醒在工具允许范围内单独提供最新3条未读原文，优先判断当前呼叫、问题和新指示。快照超出预算时保留较新的原文；展示最新消息不会授权跳过未展示的更早消息，已读水位仍按实际展示范围检查。

快照中的 `decision` 标记 `historical:true`；存在晚于该决策的新来信时标记 `stale:true`。它是历史判断，不是对当前消息的忽略指令。模型仍需更新参与决策，系统不会替模型编造新的理解。

`qq_wait_for_messages(purpose="messages")` 在允许读取未读的情况下，先返回尚未确认的现有未读（每次最多20条，`existingUnread:true`），不先等待未来消息或媒体准备。处理后用 `qq_mark_read(throughSeq=readThroughSeq)` 确认，再等待后续；回复前短静默仍使用 `purpose="reply"`。

`qq_mark_read` 确认已处理水位，不要求先完成五分钟观察。设置潜水仍由 `qq_set_wake_config` 的观察机制约束；已读不表示话题、媒体或长期记忆被删除。繁忙期间消息唤醒合并，避免对同一批旧消息逐条重放。

若“叫了却不回复”，检查收包→唤醒→实际提供的原文→读取/等待工具→模型参与判断→发送保护/额度。唤醒成功不等于已回复，内部总结也不会自动发到 QQ。

## 审核后清除

二代 Agent 识别 NSFW 后可用 update 提交 revision 和 discardMessageIds（1–10 个已展示的 messages.id）。删除当前会话近期记录、未读、工作原文、关联语义条目及媒体来源引用；争论任务已复制的独立上下文保持不变。此操作不撤回已发送给 DSH 的上下文、不清除长期插件记忆或日志，不等于入库前审核，也不保证分类或工具执行成功。
