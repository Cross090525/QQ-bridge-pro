# 接话与参与管理

控制台的“二代仿真模式 → 接话与参与”统一管理开放话题的参与尺度。普通群消息可以进入观察；观察、准备回复、实际发送是不同状态。私聊按当前来信自然回应，管理员任务模式保持独立。

## 设置

群号留空，加载和修改全局默认；输入群号后先加载，再保存单群设置。“本群恢复继承”删除该群覆盖，使它重新使用全局默认。修改输入框后需要重新加载，避免将另一范围的旧表单误保存到新群。

| 设置 | 含义 |
|---|---|
| 谨慎 | 开放话题以必要回答、具体补充为主 |
| 自然（默认） | 开放话题允许回答、补充、共鸣、贴切玩笑，不要求每次提供新知识 |
| 活跃 | 更主动参与开放话题，仍不把别人之间的交流认成对自己的邀请 |
| 玩笑与接梗 | 是否通过玩笑加入开放话题；直接与机器人交流时仍可按人设表达 |
| 共鸣与自然反应 | 是否单为共鸣或自然反应加入开放分享 |
| 无人承接的一次补充 | 默认关闭；开启后仅允许一次有必要的新补充，不连续追问 |

这些设置形成模型实时参与规则，不是每条消息的回复概率，也不是唤醒频率。实际 @、引用对象仍来自网关；语义指代、是否适合玩笑由当前 Agent 判断，不增加独立模型调用。风格与表达选项不能替代权限、白名单、暂停或发送额度。

配置保存到 `socialV2.participation`，下次消息读取、等待返回或唤醒时提供最新策略，无需重启 Bridge。已在途的旧决策遇到策略变化会要求复核。更新 preset 文件在运行中的 DSH 是否生效，仍遵循已有 preset 安装/更新流程；Bridge 的实时策略会附到后续输入中。

```json
{
  "defaults": {
    "style": "natural",
    "allowHumor": true,
    "allowEmpathy": true,
    "allowFollowUp": false
  },
  "groups": {
    "group:456": { "style": "cautious" }
  }
}
```

群覆盖在配置中可以只写变化字段，其余继承全局。控制台保存当前表单时会保存四项完整单群选择；之后需要重新继承的群可用恢复按钮。最多 128 个群覆盖，不接受私聊覆盖、未知字段或非布尔开关。

## 状态与决策

统一实现位于 `src/core/participation.mjs`，Bridge 提供会话状态和配置。模块不复制消息正文或话题库：复用现有近期消息，决策通过工作记忆验证后的来源编号关联当前交流。

- **旁听**：当前没有明确参与关系，可以判断开放话题是否适合加入。
- **被邀请**：存在明确 @ 或引用机器人的新消息，优先查看。
- **正在参与**：当前有效决策认为是延续与机器人的交流；仅对本次来源有效。
- **让出话头**：已经实际参与，先确认是否有人承接；不因同一人又发消息就默认继续。

语义分类是模型判断，网关事实优先。例如模型将一条实际 @ 别人的消息标为 direct，模块仍保留 other。状态是有期限、依赖当前消息游标的参考；当前版本不做完整多话题图或自然语言承接识别，也不以群友沉默自动学习长期好恶。

`qq_working_memory update` 的 decision 保持原有 action/note/sources，并可提供：

```json
{
  "action": "reply",
  "note": "向全群开放的问题，可以回答",
  "audience": "open",
  "intent": "answer",
  "sources": ["qq:100"]
}
```

audience：`direct / continuation / open / other / unknown`；intent：`answer / supplement / empathy / humor / follow_up`。来源仍必须由工作记忆校验，不能传任意消息或跨群引用。reply 是意向，只有发送成功才记实际参与。同一决策下的分条文本和后续表情按一次参与计数；无结构化决策的旧调用按实际发送批次计数。

## 发送前复核与兼容

普通群聊 Agent 已记录结构化决策时，实际发送队列再次检查：

1. 当前决定应为 reply；观察和补读不能直接发送。
2. 决策超过五分钟需重新判断，不长期沿用旧许可。
3. 新消息或策略变化使旧决定过时，返回 HTTP 409，先读取最新上下文，再更新 decision 后发送。只读取消息不会自动变成新的发言决定。

当前首版对决策后新到的群消息保守要求复核，不声称已能准确识别所有不相干话题；热闹群的等待与漏回需要继续实测。复核不会自动生成第二次模型调用，由当前 Agent 处理。

保护接入文本、表情、语音和统一内容发送共用的队列校验。管理员任务与已授权争论流程保留原授权路径。没有结构化决策的旧调用保持兼容，不强制额外工具调用；因此它不构成对所有旧插件的语义发言审批。既有鉴权、角色静默、白名单和额度校验继续执行。

批次中部分成功后被新消息打断，已发送部分仍记录；JSON 的 sent/failed 和 QQBridgeClient 错误的同名字段用于避免整批重发。发送失败不计作成功参与。

## 管理记录与验证

控制台仅管理员可访问 `GET/POST /api/socialV2/participation`。Agent 即使同时带控制台令牌也不能管理策略。预览不存在的群不创建活跃会话。

每会话最多保存 40 条实际参与计数、20 条动作记录，持久化在已有 `state/social-v2.json` 中；记录仅含时间、动作、固定原因分类及来源编号，不复制正文或完整思考。模型的语义分类应与实际网关对象区分；界面“准备发言”不表示已发送。明确 discard 的来源会移除相关参与记录。

展示回执和实时发言计划只在当前会话代次内有效，不从持久化记录恢复为发言许可；重启或会话替换后需要重新读取和判断。

验证命令：

```sh
npm run test:participation
npm run test:working-memory
npm run test:participation:ui
```

UI 检查沿用其他控制台测试的 Playwright 环境变量 `PLAYWRIGHT_MODULE` 与 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`，以 headless 浏览器操作合成数据。上述测试验证状态、协议和隔离；自然语言误接话与漏回仍需在 QQ 中用开放问题、明确找人、多人交错和正常来回等场景实际评估。
